{% if explainer_fr %}Calcul par blocs : traitements locaux et globaux{% else %}Blockwise computation: local and global processing{% endif %}

{% if explainer_fr %}

Un traitement local calcule le résultat en un pixel à partir d’un voisinage de taille fixe, qui ne grandit pas avec l’image. Le seuillage en est un exemple simple : il suffit de comparer l’intensité du pixel au seuil.

Un traitement global peut faire dépendre ce résultat de valeurs situées n’importe où dans l’image. Pour la segmentation par ligne de partage des eaux, les chemins reliant un pixel aux minima ou aux marqueurs peuvent s’étendre très loin : une information distante peut modifier la région à laquelle il appartient.

Un traitement local se prête trivialement au calcul par bloc. Pour un traitement global, traiter les blocs indépendamment ne garantit pas le résultat global. La thèse s’intéresse à ces traitements globaux et aux hiérarchies associées : l’enjeu est de préserver les relations entre régions tout en limitant les données chargées en mémoire.

{% else %}

Local processing computes a pixel’s result from a fixed-size neighbourhood, which does not grow with the image. Thresholding with a fixed threshold is a simple example: each pixel’s intensity is compared with that threshold.

Global processing can make the result depend on values anywhere in the image. For watershed segmentation, paths connecting a pixel to minima or markers can extend a long way: distant information can change the region to which it belongs.

Local processing can be computed block by block with a sufficient neighbourhood margin. For global processing, processing blocks independently does not guarantee the global result. The thesis focuses on these global operations and their associated hierarchies: the challenge is to preserve relationships between regions while limiting the data loaded into RAM.

{% if explainer_fr %}Comprendre la ligne de partage des eaux{% else %}Understanding watershed segmentation{% endif %}

{% if explainer_fr %}

La ligne de partage des eaux (LPE) est un grand classique de la segmentation, présent dans la plupart des logiciels de traitement d’images, libres ou propriétaires. On la retrouve notamment dans ImageJ/Fiji, ITK et Amira™/Avizo™.

Son intuition vient de l’hydrographie. On interprète une image comme un relief : l’intensité de chaque pixel devient une altitude, les zones sombres forment des vallées et les zones claires des crêtes. Une goutte d’eau descend vers un minimum ; les points drainés vers un même minimum forment un bassin versant. Les séparations entre bassins, depuis lesquelles une goutte peut rejoindre des minima distincts, définissent les frontières de la segmentation : c’est le principe de la goutte d’eau.

{% else %}

Watershed segmentation is a standard method available in most image-processing software, both open-source and commercial. Implementations include ImageJ/Fiji, ITK, and Amira™/Avizo™.

The intuition comes from hydrology. An image is interpreted as a topographic relief: each pixel’s intensity becomes an elevation, dark areas form valleys, and bright areas form ridges. A drop of water flows downhill towards a minimum; points draining to the same minimum form a catchment basin. Separations between basins, from which a drop can reach distinct minima, define the segmentation boundaries: this is the drop of water principle.

{% endif %}

En pratique, le relief peut aussi être construit à partir du gradient, qui accentue les frontières des objets. Dans la variante à marqueurs, on choisit les points de départ des bassins pour guider les régions obtenues. C’est le principe utilisé dans la segmentation interactive présentée plus loin.

{% else %}

In practice, the relief can also be built from the gradient, which emphasizes object boundaries. In the marker-based variant, we choose the starting points of the basins to guide the resulting regions. This is the principle used in the interactive segmentation discussed below.
